# Связь фигур с исходным кодом: sourceRef и syncedCommit

Каждый DDD-примитив (`uml-class`, `uml-relationship`, `bounded-context`, `context-interaction`, `aggregate-boundary`, `sequence-diagram`, `assembly-diagram`) несёт два необязательных строковых поля, связывающих фигуру с кодом: `sourceRef` — устойчивый идентификатор элемента исходников, `syncedCommit` — хеш коммита, на котором связи фигуры последний раз сверены с исходниками. Отсутствие поля означает: ссылка не задана / фигура не сверялась.

Содержимым управляют `create_shapes`, `update_shapes`, `get_canvas_state`. В `update_shapes` переданное значение заменяет, пустая строка убирает поле. Не-строка отклоняется как ошибка типа. Поля сохраняются и переживают перезапуск хранилища вместе с остальными пропсами; `get_canvas_state` возвращает их для каждого DDD-типа.

## Соглашение об идентификаторах

- **Формат `sourceRef`**: `<module>/<path>#<Symbol>[.<Member>]`, в нотации ссылок pkg.go.dev. Примеры: `terrain/server/internal/locomotion/model#Registry`, `terrain/server/internal/locomotion/model#Registry.SetDestination` (метод), `terrain/server/internal/locomotion/model#Registry.objects` (поле, в том числе непубличное).
- **`bounded-context`** ссылается на каталог контекста, без `#`: `terrain/server/internal/enetbridge` (каталог с маркерами ролей `model/`, `contracts/`, `adapters/`, `wiring/`, а не отдельный пакет).
- **Участники `sequence-diagram` и `assembly-diagram`** — любые строки на усмотрение агента; рекомендуемая форма — `pkg#Type.Method` / `pkg#Func` (для assembly — конструкторы wiring).

## Разделение обязанностей (почему нет серверной валидации)

Сервер и MCP хранят и отдают оба поля **дословно** и не проверяют ни грамматику, ни разрешимость `sourceRef`, ни значение `syncedCommit`. Проверка ссылок по исходникам, сверка изменений за период (`git diff <syncedCommit>..HEAD`), обнаружение переименования модуля и синхронизация доски с кодом — обязанность MCP-агента разработки, действующего по своим инструкциям; нерезолвящиеся ссылки — его отчётность, не ошибка OpenBoard. Основание решения: владелец инварианта «ссылка разрешима» — агент, а не доска; доска остаётся хранилищем, агент — сверяющей стороной. Семантика `syncedCommit` («все ссылки фигуры сверены на этом коммите») обслуживает инкрементальную частичную синхронизацию: общий водяной знак на доску не вводится.

## Границы и проверки

Грамматика `sourceRef` — соглашение для агента и документация, сервером не проверяется. Обратная ссылка код→доска не хранится. Поведение агента сверки (полная сверка при потере хеша, работа с нерезолвящимися ссылками) вне этого среза. Дробные размеры, автоподбор и отрисовка полей не затрагиваются — поля не видны на холсте.

Исполняемые примеры: [core tests](../packages/core/src/__tests__/source-ref.test.ts) (round-trip всех 7 типов, update-семантика, отсутствие валидации содержимого), [MCP tests](../packages/mcp/src/__tests__/source-ref.test.ts) (create/update, опубликованная схема), [HTTP/SQLite и stdio/SQLite](../apps/server/src/__tests__/source-ref-persistence.test.ts) (сохранение через перезапуск).
