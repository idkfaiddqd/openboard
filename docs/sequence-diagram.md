# Диаграмма последовательности через MCP

`sequence-diagram` хранит отдельные семантические данные об участниках и сообщениях, упорядоченных автором. Фигура показывает описание взаимодействия, а не выполняет вызовы и не проверяет доставку, синхронность или поведение изображённой системы.

```json
{"board_id":"BOARD_ID","shapes":[{
  "id":"info","type":"sequence-diagram","x":80,"y":80,"name":"Запрос карты",
  "participants":[{"id":"bridge","name":"Bridge"},{"id":"server","name":"Server"}],
  "messages":[
    {"id":"request","from":"bridge","to":"server","label":"GET_INFO(id=42)"},
    {"id":"reply","from":"server","to":"bridge","label":"INFO(id=42)","kind":"ответ"}
  ]
}]}
```

ID участников уникальны среди участников этой диаграммы, ID сообщений — среди её сообщений; это локальные ID, а не ID фигур или общие идентификаторы между досками. Имена участников и подписи сообщений могут повторяться, но не могут быть пустыми. Порядок участников задаётся массивом слева направо, сообщений — массивом сверху вниз. `from` и `to` должны обозначать разных участников той же диаграммы. В первом срезе самосообщения не поддерживаются. `kind` — необязательный текст автора, не автоматически выведенный тип или гарантия; корреляцию можно указать в подписи.

`get_canvas_state` возвращает массивы целиком. При `update_shapes` переданный массив полностью заменяет соответствующий предыдущий массив, а отсутствующее поле сохраняется. Перед удалением участника нужно удалить или переназначить все его сообщения, в том числе в одном пакете обновлений; некорректный итоговый пакет отклоняется без частичного сохранения. Пустые массивы допустимы. Удаление диаграммы не удаляет другие фигуры.

Пользователь перемещает и изменяет размер всей диаграммы; индивидуальное перетаскивание участников и сообщений пока не поддерживается. Короткий пример рассчитан на размер по умолчанию 520×360; задаваемые через MCP ширина и высота должны быть не меньше 1 единицы холста. Create schema учитывает это ограничение; при обновлении проверка зависит от фактического типа фигуры и выполняется во время операции. Автоматическое размещение длинных подписей и больших списков, фрагменты ветвлений, параллельная несохранённая правка и SVG не входят в первый срез. Дождитесь `Saved` перед обновлением страницы или следующей правкой.

Исполняемые проверки: [core](../packages/core/src/__tests__/sequence-diagram.test.ts), [MCP](../packages/mcp/src/__tests__/sequence-diagram.test.ts), [browser store и SSR](../apps/web/src/canvas/__tests__/sequence-diagram.test.ts), [HTTP/stdio и SQLite](../apps/server/src/__tests__/sequence-diagram.test.ts). Они проверяют конкретные случаи; Node store и SSR не заменяют проверку в реальном браузере.
