# Ограниченные контексты и взаимодействия через MCP

На доске `bounded-context` обозначает ограниченный контекст как явное утверждение автора; `context-interaction` — направленное взаимодействие между двумя такими контекстами. Нахождение объекта внутри рамки не устанавливает его принадлежность, а стрелка не доказывает зависимость кода или выполнение взаимодействия. Старые рамки и стрелки остаются прежними фигурами.

```json
{"board_id":"BOARD_ID","shapes":[
  {"id":"map","type":"bounded-context","x":40,"y":80,"name":"Heightmap"},
  {"id":"store","type":"bounded-context","x":600,"y":80,"name":"Chunkstore"},
  {"id":"uses","type":"context-interaction","from":"map","to":"store","label":"использует хранение"}
]}
```

Имя контекста обязательно и не может состоять только из пробелов; крайние пробелы убираются. Имена могут совпадать, идентичность задаёт ID. Размеры контекста по умолчанию 360×240; `w`, `h` должны быть положительными конечными числами. Концы взаимодействия должны обозначать разные контексты той же доски. Подпись необязательна; при обновлении пустая строка очищает её. Неизвестная подпись не означает отсутствие взаимодействия. `get_canvas_state` возвращает типы, имена, ID, геометрию, направление и подпись.

Пакет с семантическими фигурами проверяется до сохранения; неверные концы и коллизии ID отклоняются. Явно заданные ID новых контекстов могут использоваться связью раньше их в том же пакете. Удаление контекста через MCP или локально в браузере удаляет связанные взаимодействия; удаление взаимодействия сохраняет контексты. Ранее повреждённая неизменённая ссылка не блокирует несвязанные операции и не удаляется автоматически; её можно явно удалить или исправить. Прямой PATCH произвольного документа не гарантирует целостности всех ссылок.

Сценарий предполагает последовательную работу: дождитесь сохранения браузерной правки перед следующей операцией или обновлением страницы. Разрешение конфликтов одновременно несохранённых правок, межпроцессный live и SVG в этот срез не входят. Автоматические проверки охватывают отдельные операции, browser store, HTTP/SSE, stdio и SQLite; фактическая визуальная проверка браузера фиксируется отдельно.

Исполняемые примеры: [core взаимодействий](../packages/core/src/__tests__/context-interaction.test.ts) и [геометрии](../packages/core/src/__tests__/context-geometry.test.ts), [MCP](../packages/mcp/src/__tests__/context-interaction.test.ts), [browser store](../apps/web/src/canvas/__tests__/context-interaction.test.ts) и [геометрия отображения](../apps/web/src/canvas/__tests__/context-geometry.test.ts), [HTTP/stdio с SQLite](../apps/server/src/__tests__/context-interaction.test.ts). Они относятся к проверенным сценариям и не заменяют визуальные проверки в браузере.
