# Маппинг DDD-фигуры

Mapping хранит переданную внешним агентом проекцию текущих ответственностей на артефакты исходников. OpenBoard сохраняет и показывает её, не проверяя существование символов, актуальность ревизий или истинность оснований. Внешний документ остаётся источником истины. Это необязательное содержимое самой фигуры, без отдельной mapping-shape или соединителя.

Поддерживаются все семь типов: `uml-class`, `uml-relationship`, `bounded-context`, `context-interaction`, `aggregate-boundary`, `sequence-diagram`, `assembly-diagram`. Обычные фигуры отвергают явно переданное поле `mapping`.

## Структура

Экспортируемый TypeScript-тип — `DddMapping` из `@openboard/shared`. Mapping — объект с обязательными массивами `sources` и `sections` и необязательной строкой `scope`.

| Объект | Обязательные поля | Необязательные поля |
| --- | --- | --- |
| source | locator | repository, revision, description |
| section | id, title, entries[] | — |
| entry | id, responsibility, artifacts[], evidence[], gaps[] | explanation |
| artifact | locator, participation | repository, revision, description |
| evidence | claim | locator, repository, revision, method, limits |

Все текстовые поля — строки; `gaps` — массив строк. `id`, `title`, `responsibility`, `locator`, `repository`, `participation`, `claim` и элементы `gaps` должны содержать непробельный символ. Остальные строки могут быть пустыми. Неизвестные поля внутри mapping запрещены. ID разделов уникальны в mapping, ID записей — в своём разделе; строки ID сохраняются без trim. Массивы могут быть пустыми. Роли `participation` свободные: один адрес можно повторять с разными ролями. Общего реестра источников, ролей или символов нет.

## Запись и чтение через MCP

Существующие `create_shapes` и `update_shapes` принимают `mapping?: DddMapping | null` рядом с другими полями фигуры. Новых инструментов нет.

- Отсутствующее поле при создании не создаёт mapping; при обновлении сохраняет прежнее. В TypeScript `undefined` имеет ту же семантику.
- Объект полностью заменяет прежний mapping, включая удаление не переданных внутренних необязательных полей.
- `null` очищает до отсутствия `props.mapping`; само значение null не сохраняется.
- `{ "sources": [], "sections": [] }` — переданный пустой mapping, отличающийся от отсутствующего.

Например, аргументы `update_shapes`:

```json
{
  "board_id": "BOARD_ID",
  "shapes": [{
    "id": "order",
    "mapping": {
      "sources": [{ "locator": "docs/order-mapping.md", "repository": "model" }],
      "sections": [{
        "id": "ports",
        "title": "Порты",
        "entries": [{
          "id": "storage",
          "responsibility": "Сохранять заказ",
          "artifacts": [{
            "locator": "app/store#OrderStore",
            "participation": "предоставляет возможность хранения",
            "repository": "app"
          }],
          "evidence": [{ "claim": "Интерфейс найден в исходниках", "method": "чтение кода", "limits": "Поведение не исполнялось" }],
          "gaps": ["Провайдер ещё не исследован"]
        }]
      }]
    }
  }]
}
```

Непереданная геометрия и остальные поля сохраняются. `sourceRef` и `syncedCommit` сохраняют [собственный смысл](source-linking.md), не вычисляются из mapping. Некорректный mapping отклоняет весь create/update запрос до сохранения и событий успеха, включая пакет с допустимым префиксом. Это гарантия валидации, а не обещание отката после сбоя записи или потерянного ответа.

`get_canvas_state` по умолчанию и с `include_mapping: false` возвращает вычисляемый `hasMapping` у DDD-фигур, без полного mapping. При `include_mapping: true` добавляет `mapping`, если тот существует. Иной тип флага отклоняется. Обычным фигурам новые поля чтения не добавляются. Ответы create/update также краткие. `hasMapping` не сохраняется в документе; пустой mapping даёт true, очищенный — false.

Core API: `CanvasService.getCanvasState(boardId: BoardId, options?: { includeMapping?: boolean }): Promise<CanvasState>`.

Полный объект остаётся в `props` общего document snapshot: краткий MCP read не удаляет данные из SQLite, HTTP-документа или SSE. Browser и headless store используют общую runtime-схему. Отдельной таблицы или миграции всей БД для mapping нет.

## Просмотр

Значок «Отобразить маппинг» на DDD-фигуре открывает общую правую панель со всеми источниками, разделами, ответственностями, артефактами, ролями, основаниями и пробелами. Другой значок переключает фигуру. Повторный значок, крестик или Escape закрывают панель; Escape возвращает фокус на значок, если он ещё существует. Содержимое показывается как текст.

Отсутствие данных отображается как «Маппинг не передан», переданные пустые массивы — «Маппинг пуст». Открытие панели — локальное UI-состояние: оно не меняет props или геометрию и сбрасывается при уходе с доски. Панель подписана на browser store: обновление выбранной фигуры заменяет сведения, очистка показывает отсутствие, удаление фигуры закрывает панель. На узком экране панель располагается под холстом.

## Пределы и свидетельства

Работа последовательная: дождитесь `Saved` перед действием агента или повторным открытием. Конфликты одновременных несохранённых правок и межпроцессный live отдельного stdio-процесса не разрешаются этим срезом. Редактор DDD-содержимого, автоматическое разрешение ссылок, будущая архитектура, новый SVG/export и значки в headless screenshot не входят в него.

Автоматические проверки: [core](../packages/core/src/__tests__/ddd-mapping.test.ts), [MCP schemas/runtime](../packages/mcp/src/__tests__/ddd-mapping.test.ts), [HTTP/SSE/SQLite и stdio/restart](../apps/server/src/__tests__/ddd-mapping-persistence.test.ts), [browser store](../apps/web/src/canvas/__tests__/ddd-mapping.test.ts). Они проверяют конкретные сценарии; Node store и SSR не подтверждают жесты, фокус, видимость панели или autosave. Постоянный UI-автотест первой версии явно отложен; обязательная ручная приёмка реального приложения фиксируется отдельно. Ручная приёмка первой версии подтверждена пользователем: значки и панель, переключение/закрытие/фокус, пустые и длинные данные, узкий экран, HTTP MCP update/clear/delete, сохранение после перемещения и повторного открытия. Дополнительно сверены full HTTP read и SQLite. Это свидетельство перечисленных сценариев, не исчерпывающая проверка всех документов и жестов.

Ресурсы tldraw (шрифты, иконки и переводы) включены в веб-сборку через `@tldraw/assets` версии 3.15.6, совпадающей с runtime tldraw. Они загружаются с origin OpenBoard: открытие сохранённых текстовых фигур не ожидает CDN tldraw. При обновлении tldraw нужно согласованно обновлять пакет ресурсов. Это не утверждение полной автономности всех внешних встраиваний и прочих ресурсов приложения.
