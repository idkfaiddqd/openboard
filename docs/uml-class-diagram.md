# UML class diagram через MCP

UML-классы и связи представляются отдельными фигурами на доске. Содержимым управляют существующие MCP-инструменты `create_shapes`, `get_canvas_state`, `update_shapes`, `delete_shapes`; пользователь может перемещать классы и менять их размер в браузере. Работа агента и пользователя предполагается последовательной: дождитесь сохранения одной правки перед следующей.

## Данные и операции

При создании `uml-class` обязательны `x`, `y`, `name`, `attributes`, `operations`; списки содержат строки и сохраняют порядок. Необязательны `id`, положительные `w`, `h`, строковая `role` и `classifierKind` (`class` или `interface`); по умолчанию и для старых записей — `class`. Роль независима от вида классификатора. Пустые строки и дубликаты допустимы. Без размеров начальный размер — 220 × 160. `uml-relationship` задаётся через `kind`, `from`, `to`; концы должны ссылаться на UML-классы той же доски. Необязательны строки `fromMultiplicity`, `toMultiplicity`, `label`. Координаты для создания связи не обязательны.

Поддерживаемые `kind`: `association`, `generalization`, `dependency`, `aggregation`, `composition`, `realization`. Для реализации `from` — классификатор вида `class`, `to` — `interface` той же доски; она не проверяет совместимость операций или поведения. Для обобщения `from` — специализированный класс, `to` — общий. Для зависимости `from` использует `to`. Для агрегации и композиции `from` — целое, `to` — часть. Роль — текстовое обозначение, а не автоматическая классификация. `get_canvas_state` возвращает `classifierKind` для каждого UML-классификатора.

```json
{"board_id":"BOARD_ID","shapes":[
  {"id":"order","type":"uml-class","x":20,"y":30,"name":"Order","attributes":["id: UUID"],"operations":["confirm(): void"],"role":"Entity"},
  {"id":"line","type":"uml-class","x":400,"y":30,"name":"OrderLine","attributes":[],"operations":[]},
  {"id":"contains","type":"uml-relationship","kind":"composition","from":"order","to":"line","fromMultiplicity":"1","toMultiplicity":"0..*"}
]}
```

`get_canvas_state` возвращает нормализованные ID `shape:…`, содержание и геометрию. В `update_shapes` переданные поля заменяются, отсутствующие сохраняются; пустой список очищает список, пустая строка убирает необязательный текст. Повторные изменения одного ID в запросе, содержащем UML-элемент, применяются последовательно. Корректность концов реализаций проверяется по итоговому состоянию пакета; изменение, которое оставляет недопустимую реализацию, отклоняется целиком. Ошибочный UML-пакет отклоняется до сохранения; ссылка на класс с явно заданным ID допустима независимо от порядка его создания в том же пакете. Создание с коллизией ID отклоняется. Удаление класса через MCP или локально в браузере удаляет связанные UML-отношения; удаление отношения сохраняет классы. Если документ уже содержит повреждённую реализацию, она не удаляется автоматически при несвязанных операциях: её можно удалить или исправить явно. Прямое сохранение произвольного документа не проверяет целостность всех связей.

Интерфейс отображается со стереотипом `«interface»` отдельно от необязательной роли; реализация — пунктирной линией с пустым треугольником у интерфейса. Браузерное представление увеличивает класс при обнаруженном переполнении содержимого и сохраняет новый размер; автоматически уменьшать его не требуется. Подбор выполняется при отображении в браузере и не является серверным расчётом размеров. Именованный стандартный frame можно использовать для изображения границы; расположение само по себе не устанавливает семантическую принадлежность.

## Границы и проверки

Одновременные несохранённые изменения браузера и MCP не разрешаются этим срезом; предусмотренный сценарий — последовательный. HTTP MCP использует существующую SSE-шину сервера; отдельный stdio-процесс не гарантирует немедленное обновление браузера. UML-нотация в headless SVG/screenshot и панель создания фигур вне текущего среза. Механизм будущих миграций и совместимость всех исторических документов отдельно не установлены.

Исполняемые примеры находятся в [core tests](../packages/core/src/__tests__/uml-canvas.test.ts), [MCP tests](../packages/mcp/src/__tests__/uml-mcp.test.ts), [HTTP/SQLite](../apps/server/src/__tests__/uml-mcp-persistence.test.ts), [stdio/SQLite](../apps/server/src/__tests__/uml-stdio-persistence.test.ts) и [browser store tests](../apps/web/src/canvas/__tests__/uml-adapter.test.ts). Пользовательские браузерные проверки подтвердили нотацию, слои, автоподбор и сохранение в конкретных сценариях. Постоянный автоматический браузерный тест автоподбора отложен; Node store tests не проверяют отрисовку или autosave.

Для явной границы агрегата, корня и известных членов см. [границу агрегата](aggregate-diagram.md).
